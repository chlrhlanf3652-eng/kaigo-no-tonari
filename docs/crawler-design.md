# 事業者データ収集パイプライン 設計書

かいごのとなり / 2026-09-21

市区町村ページの中身は「掲載事業者データ」で決まる。ここが自動化できないと 47 都道府県 × 1,741 市区町村には広がらない。本書は、その収集・正規化・公開までの設計をまとめる。

---

## 0. 着手前に必ず確認すること

コードを書く前のゲート。ここを飛ばすと後から全部作り直しになる。

| # | 確認項目 | 確認先 | 不合格なら |
|---|---|---|---|
| 1 | robots.txt でクロールが禁止されていないか | `https://<host>/robots.txt` | 取得を諦め、公式が配布する一括ファイル or 手入力に切り替え |
| 2 | 利用規約で「複製・再配布」が禁止されていないか | 各サイトの利用規約 | 同上 |
| 3 | オープンデータ / API が別途提供されていないか | 自治体オープンデータポータル、デジタル庁 | スクレイピングせずそちらを使う |
| 4 | 掲載する情報が「公表情報」の範囲か | 出典元の公開状態 | 個人名・個人携帯などは収集対象から外す |

> **原則**: スクレイピングは最後の手段。一括ダウンロードや公開ファイルがあるなら必ずそちらを優先する。

## 1. データソース

| 優先 | ソース | 取れるもの | 更新頻度 | 備考 |
|---|---|---|---|---|
| **A** | 厚生労働省「介護サービス情報公表システム」 | 事業所名・所在地・電話・サービス種別・指定番号・定員・職員体制 | 随時 | 都道府県別サイト構成（東京都は `/13/`）。全国の介護保険サービスを網羅する一次情報 |
| **B** | 各自治体の公式ページ・オープンデータ | 区独自の制度（配食・見守り・居住支援）、相談窓口 | 不定期 | 制度内容は自治体ごとに全く違う。ページの独自性の源になる |
| **C** | 各事業者の公式サイト | 店舗一覧・配達エリア・料金 | 不定期 | 配食・見守りなど介護保険外のカテゴリはここが主ソース |
| **D** | 事業者からの直接登録 | 上記すべて＋写真・PR文 | 随時 | 掲載フォーム経由。将来の有料掲載プランの入口 |

カテゴリごとの主ソース：

| カテゴリ | 主ソース |
|---|---|
| 訪問介護・訪問看護・デイサービス等（保険サービス） | A |
| 宅配弁当・見守り・家事代行（保険外） | C → D |
| 高齢者可賃貸・居住支援 | B → C |

---

## 2. 収集の作法

一次情報源に迷惑をかけない範囲で動かす。これを守らないとブロックされて収集自体が止まる。

| 項目 | 設定 |
|---|---|
| 同時接続 | 1（並列にしない） |
| リクエスト間隔 | 2〜3秒。エラー時は指数バックオフ |
| 実行時間帯 | 深夜帯（対象サイトのアクセスが少ない時間） |
| User-Agent | 連絡先URLを含む固定文字列。匿名化しない |
| キャッシュ | 取得した生HTMLを `raw/<source>/<date>/` に保存。再パース時に再取得しない |
| 再訪問 | 同一事業所は90日に1回まで |
| 停止条件 | 403/429 を3回連続で受けたらそのソースを即停止しアラート |

## 3. パイプライン

```
[1] collect     生HTML/JSONを取得 → raw/ に保存（取得日時つき）
      ↓
[2] normalize   住所・電話・事業所名を正規化 → staging/*.json
      ↓
[3] dedupe      同一事業所の名寄せ（指定番号 → 住所+電話 → 名称類似度）
      ↓
[4] enrich      緯度経度、最寄り駅、町域タグを付与
      ↓
[5] validate    品質ゲート（4章）。落ちたレコードは quarantine/ へ
      ↓
[6] emit        data/<cat>_<pref>_<city>.json を出力
      ↓
[7] build       build.py / build_hubs.py でHTML生成
      ↓
[8] deploy      差分のみデプロイ → 変更ページのみサイトマップ更新
```

### 正規化ルール（[2]）

| 項目 | ルール |
|---|---|
| 事業所名 | 全角英数 → 半角、丸囲み数字 → 通常数字、前後の空白削除。`株式会社` の表記ゆれは保持（正式名称のため） |
| 住所 | 都道府県から始まる完全表記に統一。`丁目`・`-` の混在を `n-n-n` に寄せる。建物名は別フィールドに分離 |
| 電話 | ハイフンあり表記を正とし、`tel:` 用に数字のみの派生を生成 |
| サービス種別 | 公表システムのサービスコードをそのまま保持（`110`=訪問介護 など） |

### 名寄せの優先順（[3]）

1. 事業所番号（指定番号）が一致 → 同一
2. 電話番号が一致 かつ 住所の町域が一致 → 同一
3. 名称の正規化後編集距離 ≤ 2 かつ 住所が一致 → 同一候補として人手確認キューへ

## 4. 品質ゲート（ページを作ってよいかの判定）

**薄いページを量産しないための最重要工程。** ここを緩めると、AdSense 審査にも検索インデックスにも通らない。

| 判定 | 条件 | 処理 |
|---|---|---|
| 公開 | 掲載事業者が **3件以上** かつ 解説本文が800字以上 | ページ生成 + サイトマップ掲載 |
| 保留 | 掲載事業者が 1〜2件 | ページを生成しない。都道府県ページに「準備中」と表示 |
| 除外 | 掲載事業者が 0件 | 同上 |
| noindex | 公開後に事業者が2件以下に減った | `robots: noindex` を付けてサイトマップから外す |

追加チェック：

- 電話番号が同一市区町村内で重複していないか（コピペ由来の誤りを検出）
- 住所が対象市区町村内か（隣接自治体の事業所を誤って混ぜていないか）
- 取得日が180日以上前のレコードが半数を超えていないか → 超えたら再収集を予約

---

## 5. 更新と鮮度管理

| 項目 | 方針 |
|---|---|
| 変更検知 | レコードごとに正規化後のハッシュを保持。ハッシュが変わったページだけ `dateModified` を更新 |
| 廃止事業所 | 公表システムから消えたら即削除せず、90日間は `status: "closed"` として非表示保持。誤検知の巻き戻しに備える |
| 表示 | 各ページに「最終確認日」を明示。ここが古いままだと E-E-A-T を落とす |
| 再収集の優先度 | 更新が多い都市部 → 3か月、地方 → 6か月 |

## 6. 掲載責任まわり

実名・電話番号を載せる以上、運用として必須。

| 項目 | 実装 |
|---|---|
| 出典表示 | 全ページに出典セクションと最終確認日を固定表示（実装済み） |
| 訂正・削除の受付 | `/contact/` に掲載事業者専用の項目を用意。受付から**5営業日以内**に対応 |
| 除外リスト | 削除依頼を受けた事業所は `exclude.json` に登録し、再クロール時も復活させない |
| 写真 | 事業者から提供を受けたもの、または自前で撮影・購入したもののみ。公式サイトからの転載は行わない |
| ロゴ・商標 | 掲載しない（事業者登録プランで提供を受けた場合のみ） |

## 7. 実装の段階

| 段階 | 範囲 | 目的 |
|---|---|---|
| Phase 0 | 世田谷区 × 3カテゴリを**手作業**でデータ化 | データ構造の妥当性検証（完了） |
| Phase 1 | 東京23区 × 訪問介護 を半自動（収集は自動、検品は手作業） | 正規化ルールと品質ゲートの調整 |
| Phase 2 | 東京都全域 × 3カテゴリ を自動 | 差分更新とデプロイの自動化 |
| Phase 3 | 主要都市圏へ拡大 | 再収集スケジューラの導入 |

Phase 1 の検品を飛ばして Phase 2 に進まないこと。正規化の誤りは、生成された何千ページに等しく複製される。
